# Bug List & Issues Tracking

All entries below were found and fixed in the same working session (real production
reports and code-review findings, not hypothetical). PRD Phase 1's 19 items remain
independently verified clean.

| ID | Issue Description | Status | Resolution / Notes |
|---|---|---|---|
| 20 | `inc/updater.php` used the wrong theme slug/text domain, an undefined sanitize callback, referenced a non-existent Customizer panel, and had broken negative-cache logic; the file was also never `require`d. | Fixed | Rewritten and split into `class-gnn-github-updater.php` (class) + `updater.php` (bootstrap) per PHPCS's class-file-naming rule. |
| 21 | Elementor "Hide Breadcrumb" control used `start_injection()`, which threw a real 500 error ("Cannot add a control outside of a section"). | Fixed | Switched to `start_controls_section()` / `end_controls_section()`. Caught via `read_network_requests` before shipping. |
| 22 | Elementor template auto-heal only checked a version flag, so manually deleting all Saved Templates left the library empty forever (flag still said "installed"). | Fixed | Added an actual `get_posts()` existence check via `meta_query` on `_gnn_elementor_template`, independent of the version flag. |
| 23 | "GNN Ana Sayfa" Elementor template sections had no gap between columns; the shared `gnn_el_section()` helper defaults to `gap: 'no'` (correct for other edge-to-edge templates, wrong here). | Fixed | All 7 sections explicitly set `'gap' => 'wide'`. |
| 24 | Same template's sections used `layout: 'full_width'`, so text/columns stretched across the full browser width on wide screens. | Fixed | All 7 sections explicitly set `'layout' => 'boxed'`. |
| 25 | Stat-strip numbers and the closing CTA heading (Elementor `heading` widget) sometimes lost text-centering to `.entry-content` specificity, depending on the page/sidebar context the template was embedded in. | Fixed | Replaced with plain inline-styled HTML (`gnn_el_text()`), immune to cascade context. |
| 26 | Mobile bottom dock used mismatched Unicode glyphs (an unrelated symbol for Search; a cart emoji even for the "Contact" fallback item). | Fixed | Replaced with proper outline SVG icons matching the header's own icon style. |
| 27 | Mobile dock's `.theme-toggle` button shared the header's round icon-button CSS (fixed 34×34px, border, background), so it sat visibly higher/smaller than its plain-link siblings. | Fixed | Scoped reset: `.gnn-dock__item.theme-toggle` clears width/height/border/background inside the dock only. |
| 28 | Dock's sun icon had less visual weight than its siblings (thin 4px-radius outline core vs. bold filled shapes elsewhere). | Fixed | Core is now solid-filled at 5px radius (`fill="currentColor" stroke="none"`). |
| 29 | Scroll-to-top button was hidden behind the fixed mobile dock bar (both anchored near `bottom: 0-22px`). | Fixed | `body.gnn-has-dock .gnn-scrolltop { bottom: 86px; }` inside the mobile media query. |
| 30 | A third-party cookie-consent plugin's floating icon overlapped the dock's edge-to-edge icons in the bottom corner. | Fixed | Dock's 4 items are centered as a group with side padding (`justify-content: center; padding: 6px 28px`) instead of stretching edge-to-edge, per the user's own proposed approach. |
| 31 | Elementor's "External File" CSS Print Method silently dropped backgrounds/icons/borders (but not widget text) on hosts that restrict writes to `wp-content/uploads/elementor/css/`. | Fixed | Theme now defaults `elementor_css_print_method` to `'internal'` on `after_switch_theme` and `admin_init` (self-heals existing installs too). |
| 32 | Contact link in the mobile dock was hardcoded to `/contact/`. | Fixed | Added a "Contact page" picker (GNN Panel → Pages Layout) with auto-detect fallback for a page slugged "contact" or "iletisim" (`gnn_contact_url()`). |
| 33 | GNN Panel used a purple/indigo accent (`#6366f1`) and native checkboxes throughout, inconsistent with the requested black-and-white admin aesthetic. | Fixed | `--gnn-admin-accent` set to black; all `gnn_field_checkbox()` fields (and the updater's enable checkbox) rebuilt as on/off toggle switches. |
| 34 | Third-party admin notices (e.g. a cache-clearing plugin's success notice) rendered visually inside the GNN Panel's custom header card, between the title and the version badge. | Fixed | WordPress core relocates untagged notices to right after the first `.wrap` heading or `.wp-header-end` marker; the panel lacked that marker. Added `<hr class="wp-header-end">` after the header block so notices land below it instead of inside it. |
| 35 | The GitHub update check/"Update now" action was buried in the Advanced tab, requiring two clicks (open tab, then act) and duplicating state across two buttons. | Fixed | Single dynamic button now lives in the panel header under the version badge: "Check for updates" when up to date, automatically becomes "Update to X.X.X" when a release is available. The Advanced tab keeps only the enable/disable + Save setting. |
| 36 | After nesting the Slider CPT under the "GNN" top-level menu, clicking the top-level "GNN" link itself landed on the Slider list, not the Theme panel — WordPress wires up post-type submenus (wp-admin/menu.php) before the 'admin_menu' action fires, so the CPT's submenu claimed array index 0 ahead of our own Theme submenu registration, and WP uses that first entry as the top-level link's target. | Fixed | `gnn_panel_menu_reorder()` (late 'admin_menu' priority 999) force-sorts `$submenu['gnn-panel']` so the entry matching the parent slug ('Theme') is always index 0, regardless of core's CPT registration order. |
| 37 | "Show the dark/light toggle" (`show_toggle`) already hid the toggle button in both the header and the mobile dock, but did NOT actually lock the site to a single style: with `remember_mode` on, a visitor with a stale `gnn-theme` value in localStorage (saved before the toggle was hidden) still saw the "wrong" mode, since `gnn_head_bootstrap()` consulted localStorage unconditionally. | Fixed | localStorage is now only consulted while the toggle is actually visible (`show_toggle` on); with it off, every visitor always gets the panel's Default mode, no exceptions. Panel hints on both `show_toggle` and `remember_mode` now spell out this relationship. |
| 38 | On Left/Right Sidebar page templates, the sidebar sat 56-69px higher than the main content, growing worse the further `content_top_padding` (GNN Panel → Pages Layout) diverged from its default — `.site-main`'s own fixed `padding-top`/`padding-bottom` (meant for the plain blog listing) was never zeroed for the `.gnn-page` grid context, so it stacked on top of `.gnn-page`'s own dynamic padding instead of that being the single source of truth. | Fixed | `.gnn-page > .site-main { padding-top: 0; padding-bottom: 0; }` added, mirroring the identical fix already in place for the sibling `.content-sidebar-layout` system. Content and sidebar now top-align automatically at any configured spacing — no hardcoded pixel compensation needed. |
| 39 | `gnn_title_overlay_active()` (v1.5.0) never checked `_gnn_hide_title` or Elementor's Hide Title setting, so a page with its title explicitly hidden could still show the new "Title over featured image" overlay if the theme-wide `title_overlay_enable` setting was on — the two features were fully independent when hiding the title should override both. | Fixed | Split the hide-title check into `gnn_title_explicitly_hidden()`, which `gnn_title_overlay_active()` now checks first (returns false immediately if the title is hidden); `gnn_hide_title()` simplified to `gnn_title_explicitly_hidden() || gnn_title_overlay_active()`. |
| 40 | **Title vanished entirely** with the overlay enabled, in two cases: (a) every single blog post — `gnn_hide_title()` suppressed the in-flow `<h1>` but the overlay was rendered only by `gnn_page_featured_image()`, which `single.php` never calls; (b) any page or post with no featured image — `gnn_page_featured_image()` returns early without an image, but the title was suppressed regardless. Enabling the theme-wide setting silently removed the title from the whole blog. | Fixed | `gnn_title_overlay_active()` now returns false unless a featured image actually exists (mirroring both renderers' `post_password_required()`/`is_attachment()`/`has_post_thumbnail()` guards). Extracted the markup into a shared `gnn_title_overlay_html()` used by *both* `gnn_page_featured_image()` (page templates) and `gnn_post_thumbnail()` (single posts), so "suppressed but never rendered" is now structurally impossible. Verified all 4 combinations in Playground. |
| 41 | "Logo max height — mobile" (`logo_max_height_mobile`) was a dead setting: present in defaults, sanitized, and shown in the panel, but never read anywhere — the mobile cap was hardcoded as `34px` in main.css. | Fixed | `gnn_the_logo()` emits `--gnn-logo-h-mobile`; the mobile media query uses `min(var(--gnn-logo-h), var(--gnn-logo-h-mobile))` so the mobile value applies but can only ever shrink the logo. |
| 42 | Reading time used `str_word_count()`, which is byte-based and treats the bytes of multibyte letters as word separators — badly over-counting Turkish (ğ ı ş ö ü ç) and any other non-ASCII content, inflating the "N min read" estimate. | Fixed | Counts Unicode letter/number runs via `preg_match_all( '/[\p{L}\p{N}]+/u', … )`, falling back to `str_word_count()` only if PCRE lacks UTF-8 support. |
| 43 | `--gnn-sidebar-w`, `--gnn-boxed-width` and `--gnn-full-width` were referenced in main.css but never assigned anywhere, so they always silently fell back to their hardcoded defaults — the plumbing for configurable layout widths existed but was never connected. | Fixed | Three new panel options (GNN Panel → Pages Layout → Layout widths), clamped and emitted alongside the other layout vars in `gnn_scripts()`. |
| 44 | The block editor's "Accent" palette swatch was frozen at theme.json's shipped `#34d399`, so changing the panel's accent color updated the front end but left the editor offering the old color. | Fixed | `wp_theme_json_data_theme` filter reads the real palette back out of theme.json and swaps only the `accent` entry, leaving every other color defined in one place. Requires WP 6.1+; on 6.0 the static value applies as before. |
| 45 | The GitHub updater never populated `$transient->no_update`, so WordPress hid the "enable auto-updates" link for the theme whenever it was already current. | Fixed | `check_for_update()` now writes a `no_update` entry on the up-to-date branch (and clears it when an update is offered). |
| 46 | Pressing Escape inside a nav sub-menu called `link.focus()` immediately followed by `link.blur()` — the blur dropped focus out of the navigation entirely, stranding keyboard users on `<body>`. | Fixed | Escape keeps focus on the parent link and adds an `.is-closed` class that suppresses the `:focus-within` rule keeping the menu open; the class clears on focus-out or mouse-leave. |
